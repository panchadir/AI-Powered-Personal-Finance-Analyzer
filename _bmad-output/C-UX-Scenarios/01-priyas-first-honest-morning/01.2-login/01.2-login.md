## Overview

**Page Purpose:** Confirm that Priya's account has been created and that she is now logged in — then move her to Statement Upload as quickly as possible. This is a transition beat, not a task.

**User Situation:** Priya just submitted the Register form. She's expecting to be taken straight into the app. Any delay here is friction she didn't sign up for. The page's job is to be invisible — confirm and proceed.

**Success Criteria:** Priya sees clear confirmation that her account is ready, is authenticated automatically (no credential re-entry), and is redirected to Statement Upload within 1–2 seconds. She does not need to interact with this page — it resolves itself.

**Entry Points:**
- Auto-redirect from 01.1 Register on successful `POST /auth/register` response

**Exit Points:**
- Auto-redirect to **01.3 Statement Upload** after authentication token is set
- Error state → stays on this page with recovery option (no data lost)

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| In progress | Auth token being issued (< 1s) | Spinner visible; headline + sub-message shown | Wait (no user action) |
| Success | Token issued, session set | Smooth transition out — no intermediate "done" state visible; direct redirect to /upload | *(auto-proceed)* |
| Error — token failure | Auth server error (rare) | Error card: "Something went wrong setting up your account. **Try logging in**." + link to login page (manual fallback) | Tap "Try logging in" → /login |

---

## Data / API

| Action | Endpoint | Method | Payload | Response |
|--------|----------|--------|---------|----------|
| (Triggered by Register step) | `/auth/register` | POST | `{ email, password }` | `{ userId, token }` |
| Session establishment | *(client-side)* | — | Store token in httpOnly cookie | → redirect to /upload |

**Token from Register:** The `token` from the `/auth/register` response is set as an httpOnly cookie client-side; this page renders while that operation completes, then redirects. No separate login API call is made.

---

## Accessibility

- Progress indicator has `role="progressbar"` and `aria-label`
- Page auto-redirects — no keyboard trap; if redirect doesn't fire within 3s, a manual fallback link is surfaced
- Confirmation headline announced via `aria-live="assertive"` on mount

---

## Technical Notes

- **This page should resolve in < 1 second** — the `register` API response already includes the auth token; this page's only job is to set the cookie and trigger the redirect. If the cookie-setting logic is synchronous, this page may not even be visibly rendered.
- **Returning-user Login is a separate page** — `/login` (email + password + biometric shortcut) is used for session-expiry re-authentication and for all subsequent sign-ins. It shares visual structure with Register but is not this page.
- **No manual credential entry** — Priya registered 2 seconds ago; asking her to re-enter her password here would be a significant trust-breaking moment. The whole point is that registration = authenticated.
