## Overview

**Page Purpose:** Deliver Priya's first honest Safe-to-Spend briefing — the hero number, the plain-language "why," and her Financial Confidence Score — in a way she understands unaided, without feeling judged or overwhelmed. **The Dashboard is the primary landing page immediately after statement upload** (changed 2026-07-09 — previously the Transactions Table was), giving Priya a high-level financial summary first, with the transaction-level detail one deliberate click away.

**User Situation:** Priya just watched her statement parse. She's moved past the setup. Now she wants the answer to the question that brought her here: *"Am I okay?"* She's anxious but hopeful. She's already seen that the app is honest about uncertainty — so she's ready to believe the number if it's presented honestly. If she wants to double-check the detail behind it, "View All Transactions" is right there.

**Success Criteria:** Priya sees her Safe-to-Spend number, reads the one-sentence "why," understands the Confidence Score without explanation, and either drills into her transactions or continues to Insights — feeling informed and calmer, not more anxious, than when she arrived. WoZ gate: she can correctly explain the Safe-to-Spend number without prompting.

**Entry Points:**
- Directly from **01.3 Statement Upload** on "Go to my Dashboard" — the default landing page after a successful upload (changed 2026-07-09)
- Left sidebar (recurring access from any authenticated page)
- "See my Dashboard" from 01.4 Transactions Table

**Exit Points:**
- "View All Transactions" → **01.4 Transactions Table** (new, 2026-07-09 — see `dashboard-transactions-cta` below)
- "See my insights" → **01.6 AI Insights & Recommendations**
- "+ Add a commitment" (Upcoming Commitments card) → **02.1 Commitments Management** (Commitments is *not* a sidebar item — see the note below)
- Left sidebar: Dashboard, Transactions, Insights, Copilot — free navigation between all four from every authenticated screen, active item highlighted

## Layout Structure

Persistent left sidebar (~200px) for primary navigation, present on all authenticated pages. To its right, a **fluid** main content column (fills the browser window on laptop/desktop widths, capped generously so ultra-wide monitors don't over-stretch it): the hero card above the fold dominates, at a contained width since it's a focal number, not a data panel. Below the fold: a **responsive card grid** (not a single stacked column) — Morning Briefing, View All Transactions CTA, Spending Breakdown, and Commitments Timeline lay out side by side as the window allows, reflowing to fewer columns as it narrows. The fold is intentional — the hero number must land before Priya sees more detail; the grid is what lets the below-fold content actually use the space a desktop window offers.

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| First-visit loading | Just arrived from Transactions Table, dashboard data computing | Hero skeleton + pulse animation; "Calculating your Safe-to-Spend…" label | Wait (typically < 2s) |
| Default (data loaded) | Normal state | Hero card, briefing, insights CTA all visible | Explore, expand "Why", tap insights |
| Why expanded | User tapped "Why ₹amount?" | Inline reasoning block visible below confidence row | Read, collapse |
| Confidence drill-in open | User tapped confidence chip | Drill-in panel open, showing summary + score_events list | Read, tap chip again to collapse |
| Recurring visit (fresh data) | User returns, new data available | "Updated today" timestamp on hero freshness caveat | Normal interactions |
| Stale data warning | Statement older than 30 days | Amber banner above hero: "This is based on data from {date} — upload a new statement to refresh" | Upload new statement |
| Low confidence state | Confidence = "Watch this" | Red-amber chip; drill-in panel auto-shows on first visit with this state | Read explanation |
| Error — data unavailable | Backend failed to compute Safe-to-Spend | Error card: "We couldn't calculate your Safe-to-Spend right now. We're looking into it." | Retry, contact |

## Technical Notes

- **Two-layer Safe-to-Spend** — "today" and "after salary" are both required on the hero; presenting only one obscures the forward-looking signal that reduces end-of-month anxiety
- **Confidence Score cold-start** — on first upload (1 month of data), confidence will always be "On track" or "Watch this". This is expected and should be communicated positively: "Confidence grows with more data" — not as a failure state
- **Briefing text tone constraints** — the AI prompt must be hardcoded with the observation framing rule (no judgment language); this is the honesty moat, not a nice-to-have
- **Below-fold sections are opt-in** — the chart, transactions CTA, and commitments timeline exist for engaged users; most WoZ participants won't scroll. Don't surface them above the fold.
- **Dashboard as post-upload landing page** (2026-07-09) — this replaces the prior design where 01.3 Statement Upload's CTA led directly to the Transactions Table. Rationale: give Priya the high-level answer ("Am I okay?") before the transaction-level detail; the detail is now one click away via `dashboard-transactions-cta`, not forced.
- **Fluid, non-responsive-breakpoint layout** (2026-07-09) — the content column and below-fold card grid scale with the browser window on desktop/laptop resolutions (1366×768 up to 1920×1080+) rather than sitting in a fixed narrow column; this is implemented with CSS Grid auto-fit, not fixed pixel breakpoints, so it degrades gracefully at in-between widths too.
