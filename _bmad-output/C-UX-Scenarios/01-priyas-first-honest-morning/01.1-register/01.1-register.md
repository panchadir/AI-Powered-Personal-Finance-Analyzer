## Overview

**Page Purpose:** Convert a word-of-mouth referral into a registered, auto-authenticated user in the fewest possible steps — without triggering anxiety or demanding unnecessary personal data.

**User Situation:** Priya arrived after a colleague said "it's actually honest with you." She has her bank statement PDF already downloaded. She's cautiously hopeful, expecting another disappointment.

**Success Criteria:** Priya submits the form, auto-authenticates (via 01.2 Login transition), and lands on Statement Upload — without confusion, without feeling judged, and without entering data she considers private at this stage.

**Entry Points:**
- Direct URL / link shared by colleague (word of mouth)
- App landing page "Get Started" CTA

**Exit Points:**
- Successful registration → auto-redirect to **01.2 Login** (auto-authentication transition)
- "Already have an account?" → Login page (out-of-scenario)

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Default | Page loads fresh | Empty form, trust signal visible | User fills fields |
| Typing | User has entered some data | Fields show inline validation on blur | Continue filling |
| Loading | After CTA tap, request in-flight | CTA shows spinner, fields disabled | Wait (no cancel — request is fast) |
| Error — validation | Missing/invalid fields | Inline error messages below each field in error-red | Fix fields, resubmit |
| Error — email taken | Email already registered | Inline error on email field: "This email is already registered. [Log in instead?](#)" | Navigate to login |
| Error — network | API unreachable | Toast: "Something went wrong. Please try again." | Retry |
| Success | Registration complete | No visible state — immediate redirect to 01.2 Login (auto-authentication) | *(auto-proceed)* |

## Technical Notes

- **No username field** — email-only registration reduces friction; username can be set later in profile
- **No phone number** — not required for MVP; avoids AA-style consent prompts on first registration
- **Auto-authentication on success** — no separate "check your email" verification step for WoZ pilot; email verification can be added post-validation
- **DPDP Rule 4 compliance** — privacy notice visible and linked before data submission; no pre-ticked consent checkboxes
