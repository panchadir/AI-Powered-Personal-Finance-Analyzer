## Overview

**Page Purpose:** Guide Priya through uploading her bank statement PDF — and crucially, show her honest, transparent parsing progress so she understands *what the app did with her file* and trusts the data before she sees her first numbers.

**User Situation:** Priya just registered and was auto-authenticated. She has her bank statement PDF already downloaded. She's cautiously excited — this is the moment of truth. If the upload feels opaque or scary, she's out.

**Success Criteria:** Priya selects or drops her PDF, sees transparent parsing progress including the honest breakdown ("187 by rules, 24 by AI, 3 need your help"), and proceeds to the Transactions Table feeling confident the app understood her data correctly — not anxious about what it might have gotten wrong.

**Entry Points:**
- Auto-redirect from 01.2 Login after authentication token is set

**Exit Points:**
- Parsing complete → user taps "Review my transactions" → **01.3 Transactions Table**

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Default | Page loads, no file selected | Drop zone visible, CTA disabled | Select file |
| File hover | User is dragging a file over the drop zone | Drop zone border brightens, label changes to "Drop it here!" | Release to drop |
| Uploading | File selected, upload to server in progress | Progress steps appear, first step active (spinner) | Wait |
| Parsing | Upload complete, server parsing in progress | Progress steps advancing | Wait |
| Parse complete | All steps done | Summary card visible, CTA enabled | Tap "Review my transactions" |
| Error — wrong format | Non-PDF dropped | Toast: "Please upload a PDF — we can't read that file type" | Try again |
| Error — file too large | PDF > 10 MB | Toast: "That file is too large. Max 10 MB — try exporting a single month" | Try different file |
| Error — parse failed | Server couldn't parse the PDF | Error card: "We couldn't read this statement. This happens with some bank formats — we're working on it." + contact link | Try different statement / contact support |
| Error — network | Upload request failed | Toast: "Upload failed. Check your connection and try again." | Retry |

## Data / API

→ [data-api.instructions.md](../../../.claude/skills/wds-4-ux-design/templates/instructions/data-api.instructions.md)

| Action | Endpoint | Method | Payload | Response |
|--------|----------|--------|---------|----------|
| Upload statement | `/statements/upload` | POST (multipart) | `{ file: PDF }` | `{ statementId, parseStatus: 'processing' }` |
| Poll parse status | `/statements/{id}/status` | GET | — | `{ parseStatus, counts: { rules, ai, needs_review } }` |
| OR: WebSocket push | `ws://…/statements/{id}` | WS | — | Progress events: `{ step, status, count }` |

**Preferred:** WebSocket push for real-time step progress — avoids polling latency on mobile. Fallback: 1-second poll.

## Accessibility

→ [accessibility.instructions.md](../../../.claude/skills/wds-4-ux-design/templates/instructions/accessibility.instructions.md)

- Drop zone has `role="button"` and keyboard-activatable (Enter/Space opens file picker)
- Progress steps use `aria-live="polite"` to announce step completions to screen readers
- Parse summary announced on completion via `aria-live="assertive"`
- CTA disabled state uses `aria-disabled` not `disabled` attribute — keeps it in tab order so screen readers know it exists

---

## Technical Notes

- **PDF parsing only for MVP** — Account Aggregator (AA) flow is Phase 2; PDF upload is the WoZ baseline
- **Progress steps are real, not theatrical** — each step maps to a real server event; no fake progress animation
- **3 "needs your help" transactions** — these are surfaced in the Transactions Table (01.3), not resolved here; upload step only surfaces the count
- **File never stored unencrypted** — server must acknowledge encryption-at-rest in the upload response; display the "never leaves device unencrypted" claim only if the API confirms this
