## Overview

**Page Purpose:** Give Priya a scannable, confidence-building view of her categorised transactions — and a simple "Teach Me" mechanism to correct the 3 that needed her help — so she trusts the data behind the numbers she already saw on the Dashboard.

**User Situation:** Priya already landed on her Dashboard straight after upload and saw her Safe-to-Spend briefing. She came to Transactions deliberately — via the Dashboard's "View All Transactions" CTA or the sidebar — because she wants to verify the detail behind that briefing. She's curious, but not anxious — the transparent parsing process already built trust.

**Success Criteria:** Priya scans the list, finds at least one mislabelled merchant, corrects it via "Teach Me," and returns to her Dashboard confident her data is accurate — without needing to review every single transaction manually.

**Entry Points:**
- User taps "View All Transactions" on **01.5 Dashboard**, or selects "Transactions" from the persistent sidebar
- *(Changed 2026-07-09: Transactions is no longer the automatic post-upload landing page — the Dashboard is. See 01.3's Exit Points and 01.5's new `dashboard-transactions-cta` section.)*

**Exit Points:**
- User taps "See my Dashboard" → **01.5 Dashboard**

## Layout Structure

Sticky top bar with "See my Dashboard" CTA (always reachable — Priya shouldn't feel trapped in a review loop). Scrollable transaction list below. Filter chips for quick category drilling. "Teach Me" inline correction flow triggered by tapping a transaction row.

```
+---------------------------+
|  "← Back" | "See my      |
|  Dashboard →" (sticky)   |
+---------------------------+
|  Headline + "3 need       |
|  your help" banner        |
+---------------------------+
|  [Filter chips]           |
|  All · Food · Transport   |
|  · Subscriptions · …      |
+---------------------------+
|  [Transaction row]        |
|  [Transaction row]        |  ← rows with "?" badge = needs-review
|  [Transaction row]        |
|  …                        |
+---------------------------+
```

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Default | Transactions loaded, all rows visible | Full list, filter chips, "needs review" banner if applicable | Scroll, filter, tap to review |
| Filtered | A filter chip selected | List shows only matching category rows; chip highlighted | Clear filter, select different chip |
| Row expanded | Tapped a transaction row | Teach Me panel open below that row | Correct category, save, or tap elsewhere to close |
| Saving correction | User tapped "Got it — save this" | Spinner on save button; panel remains open | Wait |
| Correction saved | API returned success | Panel collapses; row updates in place; count decrements | Continue reviewing or proceed |
| All reviewed | needs_review_count = 0 | "Needs review" banner disappears; list returns to clean state | Proceed to Dashboard |
| Error — correction failed | API error on save | Toast: "Couldn't save that — try again" | Retry |
| Empty (edge case) | No transactions found | Illustration + copy: "No transactions found in this statement. Try uploading a different month." | Re-upload |

## Technical Notes

- **Virtual scroll** — retained as specced; originally justified by budget Android device performance. On a desktop-only MVP, a standard DOM list of 100–300 rows will likely render fine without virtualization — this is a simplification opportunity, but not applied here since epics.md's story ACs may still reference virtual scroll. Flagged for review rather than removed.
- **"Teach Me" applies to merchant** — correction is stored as a merchant-level rule (not just a one-off transaction fix); this feeds the rule engine for future statements
- **Confidence scores are not surfaced numerically** — only shown as badges (rule / AI / needs-review). Raw confidence percentages create anxiety, not trust.
- **One Teach Me panel open at a time** — tapping a second row collapses the first (no multi-edit to reduce cognitive load)
- **Fluid content width** (2026-07-09) — the content column fills the available window on laptop/desktop viewports (1366px–1920px+) rather than a fixed narrow column, so the transaction list uses the space a wide monitor actually offers; no horizontal scroll is introduced by this, since rows remain a simple flexible row layout
