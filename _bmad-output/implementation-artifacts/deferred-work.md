## Deferred from: story-1.3 planning — AD-5 httpOnly (2026-07-09)

- **True httpOnly auth cookie (AD-5 / FR-1.1) deferred to Phase 2.** The installed `reflex-local-auth==0.5.0` stores the session token in `rx.LocalStorage`, and Reflex state tokens are inherently client-visible — a true httpOnly cookie (invisible to JS) cannot come from `rx.State`/`rx.Cookie`; it requires custom server-side `Set-Cookie` middleware. **Product decision (2026-07-09, ALPHA):** Phase 1 uses a **SameSite `rx.Cookie`** (satisfies "never localStorage/sessionStorage"; not httpOnly), justified by the desktop-only/localhost/single-user threat model. Phase 2 hardening: implement server-side httpOnly session cookies via FastAPI middleware on the Reflex backend, and flip `secure=True` under https. AD-5 should be amended (or annotated) to reflect the Phase-1 SameSite-cookie baseline vs the Phase-2 httpOnly target. Consider a `correct-course` pass to formally reconcile the AD text.
- **Vestigial `_auth_token` localStorage slot from reflex-local-auth's unused `LocalAuthState` (Story 1.3, AC #3 partial).** Our real token is a SameSite cookie owned by `finance_app.state.auth_state.AuthState` (verified at `reflex run`: compiled `clientStorage.cookies` carries `_auth_token` with `sameSite=strict`). But merely importing `reflex_local_auth` for its `LocalUser`/`LocalAuthSession` models also registers the library's `LocalAuthState`, whose `rx.LocalStorage` `auth_token` compiles into `clientStorage.local_storage` as an empty, **never-written** `_auth_token` slot (nothing calls `LocalAuthState._login`; we use our own state). Security intent is met (the real token is a cookie; the localStorage slot never holds it), but the slot exists. **Phase-2 removal:** when the httpOnly server-side auth lands, replace reflex-local-auth's state layer entirely (keep only its models or fork them) so no localStorage token var is registered at all.
