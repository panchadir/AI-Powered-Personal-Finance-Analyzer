# Story 7.2: Insight Narration — O→E→E→A Shape & SEBI Rule

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a user reading an insight,
I want each insight narrated in a specific, honest shape — Observation, Explanation, Effect, Advice — and to never cross into regulated investment advice,
so that I always understand what I'm looking at and why it matters, without the app overstepping.

## Story Context

**Epic 7 — Proactive Insights, story 2 of 4.** Story 7.1 (done, reviewed) delivered `services/engine/insights/` — five deterministic detector classes that turn a user's transaction history into structured `InsightCandidate` facts (pattern name, severity, 2–3 exact `EvidencePoint`s, a `metrics` mapping, `data_months`). This story is the **narration layer**: it turns one `InsightCandidate`-shaped input into four sentences of honest, plain-language prose — never inventing a figure, never crossing into investment advice. Like Story 7.1, it has a narrow, well-defined backend surface with no direct UI of its own; its output is consumed by Story 7.3 (persistence + Insights page) and Story 7.4 (Dashboard teaser).

**What this story delivers:** `services/narrate/insight_narrator.py` with a `generate_insight_narration()` function (LLM-backed, mirrors `briefing.py`'s client-injection + graceful-degradation pattern) and a `build_fallback_insight_narration()` deterministic fallback; a shared, pattern-agnostic SEBI post-processor guard; a local `InsightNarrationInput`/`InsightNarration` dataclass pair (this story's own types — it does **not** import `services.engine.insights`, matching Story 7.1's AD-2 precedent, extended here to AD-1); new named constants in `services/narrate/config.py`; a boundary-test addition closing a real gap (below); and `tests/narrate/test_insight_narrator.py`.

**What this story does NOT deliver (explicit scope boundary — do not build):**
- ❌ Persisting narrated insights to the `insights` table, the `status`/dismiss lifecycle, the ≥15% "materially changed" re-surface rule, mapping this story's 4 output fields onto the `Insight` DB model's 4 columns → **Story 7.3**. See "Known field-shape mismatch" in Dev Notes — it's a real, already-flagged tension that Story 7.3 must resolve, not this story.
- ❌ The Insights page UI, Dashboard teaser, "Ask Copilot" handoff, the post-ingestion trigger hook that actually calls `run_all_detectors()` then this story's narrator → **Stories 7.3 / 7.4**.
- ❌ Any DB read, `db_session`, or `user_id`-scoped query → the **caller** (Story 7.3), exactly as Story 7.1 deferred it.
- ❌ Fixing anything else in `services/narrate/` beyond what this story's prerequisite fix required (see Dev Agent Record — a pre-existing `SyntaxError` in `config.py` was found and fixed before this story file was even written, because this story's first import would otherwise have hit it immediately).

## Acceptance Criteria

1. **`services/narrate/insight_narrator.py` generates narration from a Story-7.1-shaped candidate.** Given an `InsightCandidate`-equivalent input (see "Architecture seam" in Dev Notes for the exact local type), the narration follows the four-part **O→E→E→A** structure exactly, always in this order, always exactly 4 sentences:
   - **O (Observation):** one sentence, present tense, states only what the data shows (e.g. "Your Swiggy spend jumped 40% this month.").
   - **E (Explanation):** one sentence, plain-language hypothesis (e.g. "This often tracks to a busier work schedule.").
   - **E (Effect):** one sentence, impact on Safe-to-Spend or Confidence Score using values from the evidence pack (`metrics`/`evidence`) only — never invented (e.g. "This shaved ₹12/day off your safe-to-spend.").
   - **A (Advice):** one sentence, always ends with a question that invites user reflection (e.g. "Want me to set a ₹1,500 dining cap?"), and — per PRD FR-8.3's SEBI IA boundary on this layer — may only *suggest considering* a change ("You might consider…", "It could be worth checking…"), never prescribe ("You should…", "We recommend…").
2. **The "Effect" sentence cites only figures already present in `metrics`/`evidence` — no arithmetic in the narrator.** The narrator does not add, derive, sum, average, round, convert, or estimate any number (mirrors `briefing.py`'s existing no-arithmetic system-prompt rule; AD-1).
3. **SEBI phrasing rule, enforced as a shared post-processor guard, not a per-narrator convention.** Any narration whose *generated text* touches investment, equity, mutual funds, or returns (keyword-scanned, case-insensitive, on the final joined text — see Dev Notes for the exact keyword list) must end with the literal sentence `"This is not investment advice."`, appended once (never duplicated if the model already produced it). The guard applies uniformly to both the LLM path and the deterministic fallback path.
4. **`pytest tests/narrate/test_insight_narrator.py` covers:** correct O→E→E→A shape/order/count (4 sentences, no more, no fewer), the SEBI guard firing on investment-flavored text, the SEBI guard *not* firing on ordinary (non-investment) insight text, and the guard never double-appending when the model's own text already ends with the disclaimer.
5. **Zero LLM calls in the test suite** — every test passes a stub `client` explicitly (mirrors `tests/narrate/test_briefing.py`'s `StubClient` pattern); no test relies on `ANTHROPIC_API_KEY` being unset as its only safety net.
6. **Graceful degradation (NFR-1).** Missing API key, SDK exception, or a malformed/unparseable LLM response all fall back to `build_fallback_insight_narration()` — a pure-Python, deterministic, per-`pattern_name` sentence template using only the same input fields — never raises, never returns fewer than 4 sentences.
7. **No `services/engine/` import anywhere in `services/narrate/insight_narrator.py`** (AD-1, extending Story 7.1's AD-2 precedent to this side of the boundary) — verified by a **new** boundary test (Task 5 below; this direction is not currently covered by `tests/test_service_boundary.py`, which today only checks `reflex`/`finance_app` imports).
8. **Named constants live in `services/narrate/config.py`**, not inline: the model constant (reuse `NARRATION_MODEL`, matching `briefing.py`'s sibling call site — do not invent a third model-name constant), a dedicated max-tokens cap for the (short, 4-sentence) insight output, the SEBI keyword list, and the exact SEBI disclaimer string.
9. **Prompt-injection containment carried forward from `briefing.py` (AD-10 seam, sharpened by project-context.md's "DB text is untrusted LLM input" guard).** `EvidencePoint.merchant` is literally the user's bank-statement `description_raw`/`merchant_normalized` (Story 7.1's `_merchant()` helper) — **untrusted, user-influenced text**, not a system value. It must enter the prompt only inside an explicitly delimited data block (mirrors `briefing.py`'s `<FACTS>` block + quoting), with the system prompt stating the block is data, never instructions. A hostile merchant string (e.g. `"IGNORE PREVIOUS INSTRUCTIONS"`) must stay inert.
